# Finish Wiki Design

**Approved:** 2026-07-26

## Product

CAM Assistant is one native, local-first macOS assistant with three explicit
responsibility layers: personal trust/memory, coordination/judgment, and
permissioned capabilities. The wiki remains the durable personal knowledge
core; local model chat, research, repository mining, CAM/Codex, Mac Care, and
home-grown modules are integrated surfaces rather than separate products.

## Finish strategy

The verified 156-test foundation remains the baseline. Completion proceeds by
closing the real end-to-end gaps in dependency order:

1. portable repository and daily-use native wiki journeys;
2. selected local-model synthesis and claim/citation evaluation;
3. deliberate policy-gated research acquisition;
4. persistent repository jobs and evaluated semantic observations;
5. pinned live CAM/Codex execution against isolated state;
6. closed, reversible Mac Care actions and a packaged home-grown module;
7. accessibility, recovery, packaging, and final release evidence.

Every capability begins as a bounded typed path. External or mutating actions
require exact approval and deterministic postcondition evidence. Parallel
agents, graph dispatch, and reflection remain optional optimizations that must
earn adoption through frozen comparison.

## Persistence and data flow

Immutable source bytes remain in the Layer 1 content-addressed vault. SQLite
and atomic local stores hold provenance, derived-document identity, task/
research/knowledge state, approvals, coordination events, and receipts.
Replaceable indexes and model output never become source truth automatically.

Requests flow through route parsing, privacy classification, authority
selection, context assembly, proposal/approval where required, typed
execution, deterministic verification, and a status-only audit receipt.

## Failure behavior

Missing local models, network, CAM, providers, or optional modules degrade only
their capability. Cancellation and restart leave immutable inputs intact and
produce resumable state. Missing/stale approval, runtime drift, exhausted
budget, failed verification, or incomplete recovery can never report verified
success.

## Acceptance

`GOAL_FINISH_WIKI.md` is the binary completion contract.
`docs/VERIFICATION_REPORT.md` remains the living gap audit. The repository is
finished only when the native fresh-user and restart/recovery journeys,
portable aggregate verifier, privacy/retrieval/CAM/repository/Mac proofs, and
final evidence report all pass.
